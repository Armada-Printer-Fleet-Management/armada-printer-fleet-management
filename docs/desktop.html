Desktop application

The app printer operators use: a Python program that opens a native window and shows a React interface inside it. This page explains how the pieces fit and why. The rules for changing it are in apps/desktop/AGENTS.md.

Two programs, one window

The desktop app is really two programs. The backend is Python: it opens the window with pywebview and does all the work. The frontend is React: it draws the screen and nothing else. Windows runs the frontend in its own browser-engine process (WebView2), so every call between the two crosses a process boundary, the same kind of bridge Electron calls "IPC".

Why it is built this way:

  • Logic lives in one language. The backend uses the same Python domain rules as the server, so the desktop and server cannot disagree about what a print job is.
  • The screen stays thin. React never talks to a server directly; it asks the backend, which owns every connection.
  • No web server inside the app. The bridge is a direct call, so there is no port to open and nothing to secure on the operator's machine.

From source to one folder

Operators do not install Python or Node. The build packs the Python backend, its libraries and the built React screens into one folder with an .exe beside an _internal/ folder. The backend then has to find its files in two different places, so one class, Environment, answers "where is it?" for both.

The installer

Operators receive one setup program. It is built from the folder above in one more step, and installs and removes the app like any other Windows program.
