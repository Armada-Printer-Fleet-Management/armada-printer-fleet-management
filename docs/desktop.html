Desktop application

How apps/desktop/ is put together: a Python backend and a React frontend, talking over a real inter-process bridge, typed end to end by a shared protobuf contract.

This page goes deeper than apps/desktop/README.md. Read the README first for the short version; come here for the diagrams and the reasoning behind each piece.

Overview

The desktop app is two separate programs. backend/ is a Python process that opens a native window (via pywebview) and renders frontend/'s built React UI inside it. They are not one process with two halves — the rendered frontend runs inside its own WebView2 (or platform-equivalent) renderer process, separate from the Python host. Calling between them is genuine inter-process communication, the same reason Electron calls its own main↔renderer channel "IPC."

Both sides depend on packages/proto/ for their message shapes, but nothing else is shared between them — no root workspace, no linked dependency graph. Each side has its own manifest and lockfile; the only thing tying them together is generated code produced from the same .proto source.

System architecture

backend hands pywebview a single Ipc object. pywebview walks nested class instances on that object automatically (verified directly against pywebview 6.2.1), so each concrete module becomes its own namespace in JS — window.pywebview.api .application_information.version() — instead of one flat bag of methods on the root object. Adding a capability means adding one attribute to Ipc, never restructuring it.

Codegen flow

Both templates run fully offline: protoc_builtin uses the real protoc compiler installed locally (an onboarding prerequisite, like buf itself), and local: protoc-gen-es uses the plugin binary pnpm install puts in apps/desktop/frontend/node_modules/.bin/. Neither needs network access or the Buf Schema Registry. Two templates rather than one shared buf.gen.yaml, so a job that only sets up one language never has to also satisfy the other's plugin.

Running it

Mode Command What it does
Default python apps/desktop/dev_run.py pnpm build → the backend loads dist/index.html via file://. No dev server process — the closest thing to how a packaged build will eventually load its assets.
Hot reload python apps/desktop/dev_run.py --dev Starts a Vite dev server on :5173; the backend window points at it directly. Editing App.tsx hot-reloads without restarting the Python process.
