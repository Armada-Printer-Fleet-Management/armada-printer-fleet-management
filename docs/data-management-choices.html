Data management choices

Which part of the system owns which data, and how a print moves between them. This is the conceptual design; the full text, including the endpoint groupings, is data-management-choices.md.

A print's journey

Why these choices

  • Our own accounts. Users sign up with credentials this system stores, holding only what printing needs, rather than relying on an outside user database.
  • Fleet sections limit what each screen watches. Every printer belongs to exactly one section, and staff subscribe to sections, so a screen receives updates only for the printers it shows. Tags stay available for searching across sections.
  • Staff get live updates; students poll. Prints take hours and students are not watching continuously, so a cheap, cached status check is enough for them.
  • One notification per meaningful event. A job's status changes are consolidated, so nobody is flooded with email.
  • Filament is a ledger. Each student's allocation and use is recorded over time, which is what reports and low-balance warnings are built from.
