Getting set up

Run /onboarding in Claude Code or Copilot. It installs the toolchain, wires the git hooks, installs dependencies, prepares configuration, runs the tests, starts the applications, and opens this page.

If you would rather do it by hand, the skill at .claude/skills/onboarding/SKILL.md is a readable checklist. One step is easy to miss and breaks everything quietly: 

git config core.hooksPath .githooks

Hooks are per-clone and are not inherited. Without that line, none of the enforcement below applies to you.

How the code is layered

Dependencies point inward only, and CI fails a build that breaks this. The rule exists because domain logic has to run in both the server and the desktop app, which is only possible if it depends on nothing. 

packages/proto/         the API contract, no dependencies
packages/core-domain/   pure domain logic, no I/O and no framework
packages/plugin-api/    ports
plugins/                adapters
apps/                   composition roots

If domain logic looks like it needs a database or the network, it needs a port instead.

Why things are the way they are

Decisions are tracked in Jira, not in this repository. Every commit ends with the ticket it was made under, so the history is the index: run git blame on the code, read the commit message, and look up the ticket. Agents reach it through the Atlassian MCP server, which /onboarding sets up.
