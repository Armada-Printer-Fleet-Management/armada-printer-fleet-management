Web application

How the layout and routes in apps/web/ fit together, and where to add a page.

Layout

One layout route, AppLayout, wraps every page: a sidebar on the left and a <main> that scrolls on its own, so the window never scrolls. It follows the desktop app's layout, minus the collapsible rail.

File Role
src/routes.ts Every route's path, label and icon. The sidebar is built from it.
src/WebRouter.tsx Maps each path to its page. Unknown paths show not-found.
src/components/AppLayout.tsx Sidebar plus scrolling content area.
src/components/Sidebar.tsx Wordmark, New print button, navigation, Sign in or Sign out.
src/pages/ One file per page.
src/lib/auth.ts, auth-context.tsx, api.ts The sign-in session, the React state built on it, and the one API client that sends its token.

Add a page

  1. Add an entry to routePaths in src/routes.ts. Use nav: 'main' to show it in the sidebar.
  2. Create the page in src/pages/.
  3. Add a <Route> for it in WebRouter.tsx.

Signing in

Pages open without signing in. The sidebar's Sign in sends the student to Keycloak's login page and back, using the standard OpenID Connect code flow with PKCE. Keycloak is served under /auth on the app's own address, so the browser never talks to another site, and the server trusts tokens issued for that same address.

  • The token is read on every request, not once when the client is built, so a renewed token is always the one sent.
  • Signing in is only a UI state in the browser. What a signed-in user may do is decided by the server, which checks every token itself.
  • Nothing here names a provider. The API client takes any function that returns a token, and the sign-in library speaks plain OpenID Connect, so another provider is a change of settings, not of code.

Dev tools link

In pnpm dev the sidebar shows a highlighted Dev tools link to /temp, the integration check against the server. The route is behind import.meta.env.DEV and loaded lazily, so pnpm build leaves its code out of the bundle.

Colours

The web app uses the shared tokens in packages/ui-kit/src/styles.css, with one override: --primary is the design's red in src/index.css. The desktop app keeps the shared blue. Anything that should follow the brand colour must use bg-primary or text-primary, never a literal colour.
