Conventions the schema follows

Domains link by ID only

Solid lines are real foreign keys inside a domain. Dashed lines cross a domain and carry only an ID, so the ledger can store a print_job_id without knowing anything about jobs.

An ID is named after what it points at

A column holding one of our IDs is <entity>_id, with no prefix: printer_id, never assigned_printer_id. Identifiers from outside, such as Keycloak's, end in _ref. The one exception is the audit log's and broadcast's target_type + target_id pair, which can point at several kinds of thing.

One source for each fact

Who did something and when lives in the event and audit tables, not copied onto every row. Timestamps are kept to a small shared set: created_at, updated_at, deleted_at and expires_at.

History is append-only

AuditLog, PrintJobEvent, PrinterEvent and FilamentLedgerEntry are never updated or deleted. Balances come from the ledger, and a job's actual time and filament are the sum of its PrinterEvent attempts.

Enums are fixed UUIDs

An enum column stores a UUID that never changes, never a number or a name, so renaming a value can't change what existing rows mean. Lists that differ between institutions, such as queue types, are data instead.

Secrets stay out

Keycloak holds passwords, sessions and tokens. Queue join codes are hashed. File storage keys are opaque, and download links are never stored.

Open questions

Found while drawing the schema and still undecided. The diagram shows the schema as it stands.

Notification

Broadcast → Notification has no column

A broadcast fans out into one notification per recipient, but notifications don't record which broadcast made them. A nullable broadcast_id would fit, since both tables are in the same domain.

Filament Allocation

Materials are enums

A filament material's type and colour are enums, but materials differ between institutions, which by the convention above makes them data. One of the two needs to change.

Not stored

Two domains have no tables

Reporting and real-time status are part of the design but read other domains' data or the printer server, so they have no tables of their own.

What this diagram is for

It is the core picture of the data, not a record of every design decision. The code is the source of truth. When a domain, entity or table changes, this page changes with it; finer detail stays in the code.
