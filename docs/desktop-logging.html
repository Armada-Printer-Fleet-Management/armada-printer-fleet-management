Desktop logging

How to log from the desktop backend, what each level means, and where the log files end up. A quick reference; the wider app is described in Desktop application.

How to log

Use Python's standard logging module. There is nothing of ours to import, so this works the same in domains, infrastructure, IPC modules and the app itself. 

import logging

logger = logging.getLogger(__name__)  # once, at the top of the file


class PrintJobService:
    def approve(self, print_job_id: PrintJobId) -> PrintJob:
        logger.info("Approving print job", extra={"print_job_id": str(print_job_id)})
        try:
            ...
        except ServerNotConfigured:
            logger.exception("Could not approve print job")
            raise
  • logging.getLogger(__name__) returns a logger named after the module, such as armada_domains.print_job.service. That name is the logger field in each log line.
  • extra={...} adds your own fields. Each key becomes a top-level field in the JSON line, which makes it searchable.
  • Pass values as arguments: logger.info("Queue %d%% full", percent), not an f-string. The text is only built if the record is written.
  • Never log personal data: no names, emails or file contents. IDs are fine. Users send these logs to developers.
  • Never import ApplicationLogger. It is set up once at startup in armada_app/__main__.py.

Log levels

Call Level Use it when Dev Packaged
logger.debug() DEBUG Detail that only helps while developing: values, branches taken Written Dropped
logger.info() INFO A normal event worth a record: an action started or finished Written Written
logger.warning() WARNING Something unexpected that the app recovered from Written Written
logger.error() ERROR An action failed Written Written
logger.exception() ERROR An action failed, called inside except; adds the traceback Written Written
logger.critical() CRITICAL The app cannot carry on. Uncaught crashes on any thread are logged at this level automatically Written Written

What a log line holds

Each record is one JSON object per line (JSON Lines). In dev the same record also prints to the terminal as readable text. 

{"timestamp": "2026-11-01T22:22:02.290832+00:00", "level": "ERROR",
 "logger": "armada_domains.print_job.service", "message": "Could not assign print job",
 "module": "service", "file": "service.py", "function": "assign", "line": 27,
 "process": 46924, "thread": "MainThread",
 "exception": "Traceback (most recent call last): ...",
 "print_job_id": "3f2a9c1e-..."}

Timestamps are UTC. file is the file name only, and the user's home folder in messages and tracebacks is written as ~, so no username leaves the machine.

Where to find logs

Run with Log folder
Dev: python apps/desktop/dev_run.py (with or without --dev) apps/desktop/logs/ in the repository (gitignored)
Packaged: the built .exe or the installed app %APPDATA%\<exe name>\logs\

The file is <exe name>.jsonl. At 5 MB it rolls over to .jsonl.1, keeping four backups. To follow it live in PowerShell: 

Get-Content apps\desktop\logs\*.jsonl -Wait -Tail 5
Get-Content "$env:APPDATA\Armada-Printer-Fleet-Management\logs\*.jsonl" -Wait -Tail 5

The packaged app has no console window, so it writes to the file only. To see output live while debugging a build, set console=True in desktop_backend.spec and rebuild; do not commit that change.

Checking it by hand

Open Settings → Diagnostics in the app.

  • Write test log entry writes one INFO record, "Test log entry from the Settings page" with "source": "test_button". Look for it in the log folder above to confirm logging works in that build.
  • Export logs opens a Save dialog and writes a zip of every log file plus manifest.json (app, version, dev flag, OS, Python version, export time). This is what users send to developers.
